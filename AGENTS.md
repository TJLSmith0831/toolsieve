# toolsieve — Agent notes

Semantic MCP tool router: aggregates downstream MCP servers, exposes exactly
3 tools (`find_tools`, `call_tool`, `get_savings_report`). Python 3.11+, uv,
FastMCP.

## Commands (verified 2026-07-27)
- Install: `uv sync --group bench` (bench group adds tiktoken + rank-bm25, needed by benchmark tests)
- Test all: `uv run pytest -q` — 85 tests, real MCP servers over stdio + local HTTP, no mocks, no network egress
- Test one file: `uv run pytest -q tests/test_setup_toolsieve.py`
- Demo end-to-end, no config needed: `uv run python demo.py`
- No lint/typecheck is configured — don't go looking for a `ruff`/`mypy` invocation, there isn't one
- Full benchmark (slow — downloads a real embedding model): `uv run --group bench python benchmarks/run_benchmark.py && uv run python benchmarks/render_results.py`

## Map
- `toolsieve/server.py` — MCP entry point; the 3 exposed tools live here
- `toolsieve/aggregator.py` — connects to every downstream server, builds the tool `Catalog`
- `toolsieve/router.py` — embedding match + `Savings`/token accounting
- `toolsieve/config.py` — `mcpServers`-shaped config + `.env` loading (GH #6)
- `toolsieve/oauth.py` — token store + the browser-less `NonInteractiveOAuth` the server uses
- `toolsieve/auth_cli.py` — the `toolsieve-auth` console script: the only place a browser opens
- `toolsieve/setup.py` — the `toolsieve-setup` console script: migrates a client's existing MCP config (Claude Code/Desktop, Cursor, Windsurf, VS Code, Codex CLI) into toolsieve's, and `--verify` checks the result
- `tests/fake_server.py` — the real stdio/HTTP MCP servers the test suite runs against
- `benchmarks/` — routing-accuracy benchmark (naive vs BM25 vs toolsieve); see `benchmarks/RESULTS.md`

## Gotchas
- Code comments cite decision IDs like `(D8)` / `(GH #6)`. The `D#` docs live in `openspec/changes/`, which is **gitignored and local-only** — a fresh clone or worktree won't have them. Treat the ID as a pointer that may be unresolvable, not a broken link to chase down.
- `.env` only fills gaps: a real exported env var always wins over it (`toolsieve/config.py:expand_env`).
- An unset `${VAR}` in config is a hard error naming the server + var — never silently substituted as empty.
- `CHANGELOG.md` and GitHub Releases are generated by CI on merge to main (`.github/workflows/changelog.yml`, `release.yml`) — don't hand-edit the changelog for work that isn't merged yet.
- PR titles need a conventional-commit prefix (`feat:`, `fix:`, `docs:`, …) — the changelog bot parses it. See `CONTRIBUTING.md`.

## Do not touch
- `uv.lock` — regenerate via `uv sync`/`uv add`, never hand-edit.
- `benchmarks/results.json`, `benchmarks/RESULTS.md` — written by `render_results.py`, not hand-authored.

## Operating rules
- Read before writing: trace the real flow before editing; grep callers before changing a shared function.
- Reuse before writing: search for an existing helper/pattern in this repo before adding one. Match local idiom over general best practice.
- Shortest working diff: no speculative abstractions, no unrequested refactors, no drive-by cleanups. One concern per change.
- Targeted reads: open the specific files/sections you need, not whole directories. Search first, read second.
- Scoped verification: run the narrowest check that proves the change (single test file > full suite) — then the full gate only before done.
- Claim only what you ran: "done" means executed and observed. If not run, say "not run".
- When a task is ambiguous, state your assumption in one line and proceed; don't build both interpretations.
- Use the `/ponytail:ponytail` skill whenever coding — it's this repo's binding convention, not just a suggestion.
